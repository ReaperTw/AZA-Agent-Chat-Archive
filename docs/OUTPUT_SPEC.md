# 網頁匯出輸出規範

四站 userscript（ChatGPT、Claude、Gemini、Grok）共用的輸出契約。內容可見性與來源驗收依 [`../AGENTS.md`](../AGENTS.md) 與 [`EXPORT_VALIDATION.md`](EXPORT_VALIDATION.md)；本檔只規範**輸出長什麼樣、哪些規則四站相同、哪些允許不同**。

原則：使用者只在乎產出的對話內容，不在乎用哪種方式取得。API、DOM、COM 三種匯出產生同一種格式的檔案；COM 只是讓結果更可靠的保險。

## 1. 共用與站點差異的界線

| 層 | 規則 | 四站 |
| --- | --- | --- |
| 擷取 | API 協定解析、DOM 選擇器、分支判定、捲動載入 | 各站自有 |
| 整合策略 | ChatGPT：DOM 正文＋API ID／角色／順序核對，未配對 API 放文末附錄。其餘三站：API／DOM 正文比較，衝突兩版並列、單邊訊息原位保留 | 依平台契約，允許不同 |
| 渲染 | 檔頭、訊息分隔、補充資料、佔位字、不完整標記 | **必須相同**，由共用模組產生 |
| 交付 | 檔名、報告、選單順序、版本顯示 | **必須相同** |

站點腳本只負責把資料轉成下方「訊息模型」，渲染一律交給共用模組。

## 2. 訊息模型

```text
Message {
  role: 'user' | 'assistant'
  text: string                // 可見正文 Markdown
  time?: string | Date        // 該則時間；只用於計算檔頭時間範圍
  citations?: Ref[]           // 引用
  attachments?: Ref[]         // 附件
  process?: Ref[]             // 已證明可見的處理狀態
  note?: string               // 站點必須告知讀者的單則說明
}
Ref = string | { label?|title?|name?|file_name?, url?|href?|links?, type? }
```

## 3. 對話檔（API／DOM／COM 共用）

```markdown
> **對話時間**：2026/11/8 下午6:04:06 – 下午6:15:27
>
> **來源網站**：ChatGPT
>
> **網址**：https://chatgpt.com/c/…

--- [User 1] ---

正文

--- [Model 1] ---

正文

引用：[NHS](https://…)；PubMed

附件：report.pdf
```

1. **檔頭**：依序為對話時間、來源網站、網址，缺少的項目略去。時間取第一則到最後一則，同一天時結束只寫時刻。網址去掉 `#` 片段。不寫擷取方式、匯出來源、核對結果、注意清單或免責說明；三種匯出的檔頭格式完全相同。
2. **不完整標記**：只在內容確定有缺漏時，於檔頭後加一行 `> **不完整**：{原因}`，多個原因以「；」連接、去重。觸發條件：
   - 歷史未取完整（DOM 未捲到第一則、API 只回傳部分歷史）
   - 目前分支未確認
   - 有無法辨識而未輸出的內容
   - ChatGPT 沒有頁面正文、API 內容只能放在附錄
   以下**不寫入**對話檔，只放報告：某一來源失敗但另一來源完整、正文差異筆數、結構核對細節、缺少時間戳、相對時間、「已排除 N 則思考前置進度」等資訊性提示。
3. **訊息分隔**：`--- [User N] ---`／`--- [Model N] ---`，與本機 Skill 匯出一致，User 與 Model 各自編號。
4. **單則標記**：只在雙來源都有、且該則為單邊時，加 `> 僅 API 有此訊息` 或 `> 前進度；僅 API 有此訊息`。衝突時加 `> **來源衝突，兩版並列**`，再接 `### API 版本（role）`／`### DOM 版本（role）`。單一來源匯出不標來源。
5. **補充資料**：每類一行，接在正文後。
   - `引用：`有網址時寫 `[名稱](url)`，沒網址時寫名稱（去掉 `+N` 尾碼）。已出現在正文的網址，以及 `[cite: N]` 類標記，一律略去。
   - `附件：`寫名稱。沒有名稱的圖片指標略去（正文已有佔位字）；其他無法辨識的形狀以單行 JSON 保留。
   - `處理狀態：`同上規則。
   - 同一則的 API／DOM 補充資料合併去重。不輸出逐則時間，也不輸出多行 JSON 區塊。
6. **佔位字**：一律使用 `> [圖片]`、`> [文件]`、`> [附件]`、`> [非文字內容]`、`> [非文字內容：摘要]`、`> [非文字回答]`。不寫「本體未嵌入匯出檔」之類的說明。
7. **站點標記**：Gemini 檔案引用標記 `[cite: N]`、`[cite_start]` 在程式碼區塊外移除。
8. **ChatGPT 附錄**：未配對的 API 內容放在 `## 待確認 API 內容（不屬於正式正文）`，每則一個 `### 待確認 API #n（role）`，以 fence 保留原文。

## 4. 報告（偵錯用）

- 報告是純文字的核對細節，包含來源數量、各來源取得狀態、差異全文、引用／附件計數，以及所有未寫入對話檔的提示。
- 綜合對話框另存的 API／DOM 副本，內容與單獨 API／DOM 匯出相同（§3 格式），只靠檔名區分。

## 5. 交付

- 日常檔名：`{站碼}_{對話名稱}_{yyyyMMdd_HHmmss}.md`，API、DOM、COM 三種匯出都一樣，不標模式，也不加 `_INCOMPLETE` 等尾碼（不完整只寫在檔頭）。站碼為 `GPT`／`CLD`／`GEM`／`Grok`。
- 偵錯另存：綜合對話框另存的副本與報告，在日常檔名後加 `_API`／`_DOM`／`_REPORT`，避免同一秒存檔撞名。
- 舊檔改名由轉換工具處理（ticket 05），執行前列清單給使用者確認。
- 工具選單由上到下：到頂端、綜合匯出、API 匯出、正常匯出。
- 版本顯示：`@version` 與按鈕提示一致，格式為 `AZA-Agent-Chat-Archive - {站名} {版本}`。版本只遞增最後一位。

## 6. 驗收

- 共用渲染以 fixture 測試鎖定：同一份訊息模型在四站、三種匯出方式產生**逐字相同**的對話檔，只有來源網站一行不同。
- 不完整標記以 fixture 測試鎖定：§3.2 列出的觸發條件會產生該行，不觸發的情況不產生。
- 站點擷取仍依 `EXPORT_VALIDATION.md` 做三來源驗收。未完成即時登入驗收時，必須明確標示。
