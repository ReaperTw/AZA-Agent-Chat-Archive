# 變更與回歸檢查清單

每次修改前先用這份清單圈出影響範圍；交付前逐項核對。通過才勾選，並附證據；未通過、未驗證或不適用則記錄原因。網頁輸出跟隨[輸出規範](OUTPUT_SPEC.md)，驗證方法與平台例外依[匯出驗收規格](EXPORT_VALIDATION.md)。

## 一、改動前

- [ ] **界定範圍**：列出受影響的站點／本機 harness、入口與模式（API、DOM、COM、遷移）。若改動共用層，列出所有使用它的入口，不只檢查發現問題的站點。
- [ ] **建立基準**：寫下使用者看得到的錯誤、原本應保留的行為，以及預期產物。修 bug 時，用最小可重現樣本確認舊版會失敗；不要只比總則數或只確認能下載。

## 二、依改動勾選

- [ ] **正文擷取／格式**：同時檢查 User 與 Model。用含純文字、項目符號、編號清單（不同起始值或重新起算）、換行／縮排、行內與區塊程式碼的樣本，核對文字、順序和有意義的空白。檢查由瀏覽器渲染、`textContent`／`innerText` 不一定包含的內容，例如清單編號。
- [ ] **可見性／補充資料**：可見內容不漏抓；隱藏推理、工具內部資料與操作文案不混入正文。引用、附件和已識別的進度分開驗證；未知內容不靜默捨棄。
- [ ] **歷史／分支／排序**：同一對話、同一選取分支，從第一則到最後一則，依角色、順序與可用 ID 核對。驗證延遲載入、換對話或停止時，不會把部分結果宣稱完整。
- [ ] **比較／整合**：渲染等價的輸入應相符；改一個字、清單編號或有意義的空白，仍須得到相應差異。驗證衝突、單邊來源或來源失敗按各平台契約處理。不要靠放寬正規化消掉警告。
- [ ] **Markdown／下載／共用渲染**：查實際產出的 Markdown 與檔名，不只看按鈕或對話框。適用時核對單獨匯出與另存副本；改到共用渲染時確認各站內嵌產物同步，版本與介面提示一致。
- [ ] **本機匯出／舊檔轉換**：用合成資料跑受影響的匯出或預覽入口。核對檔案、分隔及正文；轉換只改允許的欄位，再跑一次不得產生額外變更。

## 三、交付前

- [ ] **驗證走過實際入口**：執行對應回歸；涉及網頁擷取或下載時，在隔離瀏覽器操作受影響的功能。網頁三來源依驗收規格核對；分開標示合成、重播、即時登入結果，不把重播或則數相等當成完整驗收。
- [ ] **留下可重做的證據**：記錄命令／操作、結果與未驗項目。真實對話、登入資料、原始回應只留私人暫存；版本庫只放合成測試或去識別結果。有新回歸類型時，補在對應的通用項目。

## 交付紀錄格式

```markdown
- 變更／版本：
- 影響範圍（入口、模式、共用層）：
- 回歸樣本與預期：
- 驗證證據（合成／重播／即時；命令或操作 → 結果）：
- 未通過／未驗證／不適用（項目與原因）：
```
